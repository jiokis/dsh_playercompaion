# 剧情自动总结

## 何时使用

用户要求总结刚录制或历史录制的游戏剧情，尤其是：

- 一场很长的录制，手动逐句看不完；
- 需要先判断这一场大致讲了什么；
- 需要把长文本整理成分场景梗概；
- 需要区分主线/世界任务场次（先看场次的 quests.json 映射）。

## 步骤

1. 先调用插件工具：

   ```
   lore_story { action: "auto", game: "hsr", session: "watch-YYYYMMDD", limit: 10 }
   ```

   - 返回按时间切片的 `arcs`、`characters` 和可直接阅读的 `text`。
   - 这是抽取式速览，不是润色稿；不要把它当最终文学稿。

2. 检查 `stats.lines`、`arcs` 和 `warnings`：
   - 行数为 0：没有该场次录制，不要编造。
   - 场次跨主线/世界任务：先读 `<dataDir>/journal/quests.json`，不要合并。
   - OCR 噪声明显：用 `lore_story search` 核对关键词。

3. 需要正式梗概时：
   - 将日志按时间或行数切成 4–6 块；
   - 每块用子代理写 500–900 字场景梗概；
   - 主代理合并为 6–10 个阶段，保留“未解决/存疑”；
   - 写入 `synopsis.json`（原神）或 `hsr-synopsis.json`（星铁），并同步到实际 dataDir。

4. 交付时说明：
   - 场次、时间、原始行数；
   - 哪些是 OCR 存疑；
   - 哪些内容未在录制中，不补写。

## 约束

- 只读本地记录；不抓取新画面，不上传。
- 不发明未录制的剧情、角色或关系。
- 抽取式速览与文学梗概要明确区分，别把前者说成后者。
- 主线/世界任务按场次映射分开；不要用主线梗概覆盖世界任务场次。
